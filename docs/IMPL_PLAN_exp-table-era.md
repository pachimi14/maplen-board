> 1計画書=1縦切りテーマ(PR-001)。テーマ=**「EXP テーブル era の正確性」**。
> 承認者: ユーザー(2026-07-27 承認) / 実装: implementer / 統括が code-review+実測で検収。

## 0. 目的と背景

- **要件を一文で**: 2026-07-23 のゲーム側 EXP テーブル 20%減を境に、**日次 EXP 増加量と EXP% が era 正確に計算される**ようにし、過大/過小の誤表示を解消する。
- **北極星への寄与**: 「毎朝見る」中核数値(日次 gain・ランキング・グラフ)の**正確性**の回復。現在ユーザーが見ている値が誤っている。
- **根本原因(実測確定)**: `level_exp.py` の progress 計算が **in-level exp を「現行(20%減)テーブル」の必要値でクランプ**し、`analysis.py` がその差分を日次 gain として**全履歴に適用**している。`db0ed3d` は旧テーブルを `LEGACY_EXP_TO_NEXT_LEVEL_PRE_2026_07_23` として残したが、**gain 本経路は日付非対応のまま**(legacy は production 未参照=デッドコード)。

## 2. 設計(確定・逸脱禁止)

### 2.1 日次 gain の単一式
```
gain(d) = P(T_d, level_d, exp_d) − P(T_d, level_{d−1}, exp_{d−1})

  P(T, level, exp) = Σ T[225 .. level−1] + exp      ← クランプしない
  T_d = snapshot_date ≤ "2026-07-22" ? LEGACY : CURRENT   (行き先日 d の表)
```
**この1式が全ケースを厳密に被覆する**(統括が代数+実データで確認):
- **同 era・同レベル** → テーブル項が相殺 → **raw exp 差**(厳密)
- **同 era 内レベルアップ** → その era の必要値で区間計算(厳密)
- **境界の同レベル** → `T_d`=新表が両辺で相殺 → raw exp 差(厳密。実測「減少0」と整合)
- **wake-up 日(保留レベルアップ)** → 非クランプゆえ `P(新,251,3736B) = P(新,252,499B)` と**連続**し繰越を自動処理 → **§0 の +142B 級の過大が構造的に消える**
- **境界をまたぐレベルアップ(1,474人=境界日キャラの19%)** → 新表基準は**保守的下限**。真値 ∈ [計算値, 計算値 + 0.2×旧必要値]。**過大は構造的に0**(LULU-054 の「保守的fallback・過大ゼロ」と同じ誠実性特性)

### 2.2 実装形(波及の抑制)
- `level_exp.py` に **追加のみ**: `EXP_TABLE_CHANGE_BOUNDARY = "2026-07-23"` / `exp_table_for(snapshot_date)` / **テーブル引数付き・非クランプの progress・percent プリミティブ**。
- **既存の現行表固定関数はシグネチャ・挙動とも不変**(planner ETA・最新日 totalExp 等の「今後の見積り/最新日」用途)。
- `analysis.py` と `mvp_export.py`(history percent)だけ era 対応版へ切替。
- **`v2_recovery_backward.py` の私製 progress 実装(クランプ付き)を新プリミティブへ統合**し、progress の正を1箇所にする(ドリフト解消)。

### 2.3 EXP% の方針(ユーザー裁定 2026-07-27)
- **再計算した正しい % を出す。非クランプなので 100% 超はそのまま表示**(例 115.4%)。Navigator の遅延表示には合わせない。
- **レベルの捏造禁止**(「Lv252・499B に正規化」は API が報告していない状態を作るため**不採用**)。欠損化も不採用(値は判明しているため)。
- **想定上限 125%**(=1/0.8)。web は **プログレスバーの視覚幅を `min(100, pct)` でクランプ・数値は真値**を表示。
- `rankingUtils.js:169` 付近のプランナー残exp見積り `1 − percent/100` が**負になる**ため **`max(0, …)` ガード必須**。
- **新規ロケール文言は追加しない**。

### 2.4 維持する既存仕様
- **負 dailyGain → null**(LULU-057)は維持(era 厳密化後の負は genuine な異常のみ)。
- 加算セマンティクス・重複集約(P-DQ-1)・部分UNIQUE制約(P-DQ-3)は不変。

## 3. 変わってよいもの・いけないもの

- **変わってよい**: pre-patch 期間の `dailyGain`(≈70,993ペア)/ history の `levelExpPercent`(pre-patch は相対 ×0.8 方向へ)/ 100%超の出現(381行)/ weekly・monthly(日次 gain の和なので自動追随)/ 日次 gain ランキング順位(**正しくなる方向**)。
- **変わってはいけない**: **最新日の `rank`/`exp`/`level`/`totalExp` 系**(0件変化)/ v2 スキーマ / 取得挙動 / DB の raw 値 / 6ロケールのキー集合 / **同レベルペアの gain が raw exp 差と一致すること**。
