## C1. 案A — 価値ベース表示の明確化(計算変更なし)

背景: PC換算レート>1のとき「1人あたり基準額」(PC換算込みの価値)が実際に受け取れるNESOより大きく見え誤解を生む(ユーザー報告)。数学は正しく、**表示の役割分担のみ**を直す。

1. **ヒーロー2枚目のラベル**: 既存キー `raffle.baseShare` の文言を「1人あたり基準額」→「**1人あたりの分配価値（PC換算込み）**」へ6ロケール修正。タイル内に小さく1行(新キー `raffle.baseShareNote`)「実際の受け渡しは送金一覧のとおり」
2. **メンバーカードにPC換算内訳**: 当選総額の下に、`member.powerCrystalNeso > 0` のときだけ「うちPC換算 {amount} NESO（送金対象外）」(新キー `raffle.pcPortionNote`、値は既存 `powerCrystalNeso` を表示するだけ。再計算しない)
3. **サブ指標に「実際に動くNESO合計」を追加**: `calculation.transfers` の金額合計(BigInt加算のみ、新キー `raffle.actualTransferTotal`)。表示位置は送金可能NESOの隣
4. メンバー別詳細テーブルは変更しない(既にPC列に「交換・送金不可」注記あり)

対象: `SettlementResult.jsx` / `raffle.css`(必要なら) / 6ロケール。`settlement.js` は不変。

## C2. 精算結果の画像コピー(1ボタン)

背景: 現在はPTメンバーが各自スクショして共有している。EXPランキングの共有画像(T7)のように**1ボタンでクリップボードへ画像コピー**したい。

### 仕様

- ボタン設置: 精算結果(`SettlementResult`)ヘッダー右側に「**結果を画像でコピー**」(新キー)。クリックで PNG を生成し `navigator.clipboard.write`(ClipboardItem)。**失敗時(非secure context含む)は自動でPNGダウンロードにフォールバック**し、その旨をトースト的テキストで表示(T7 の既存フォールバック文言/機構が再利用できるか実装時に確認し、可能なら再利用。**クリップボード/ダウンロード処理の正はT7実装に一本化**できるなら共通化、密結合になるなら raffle 側に薄い複製を置かず共通ヘルパーへ抽出)
- 画像内容(上から): タイトル「Raffle Settlement」+ ボス表記(例 `Hard Will + Eternal Ascendant`)+ 開催回(ローカル+UTC) / 合計価値・分配人数・PC換算レート(「PC換算込み」明記=C1と整合) / メンバー別行(名前・当選総額・うちPC換算・支払う/受け取る/精算不要+金額) / 実際の送金一覧(A → B 金額) / フッター `lulumi-tools.com`
- 描画: **canvas 直描画**(T7方式)。外部画像は使わない(キャラ画像なし=CORS taint リスクなし)。幅1200px固定・高さは行数で可変(メンバー≤6・送金≤n-1で有界)
- 言語: **現在の表示ロケールで描画**(T7の英語固定とは目的が違う=PT内共有のため。X共有機能は付けない)
- 配色: light固定(共有先の見やすさ優先・T7と同様に背景を塗る)
- 新規npm依存 禁止(html2canvas等は使わない)

### 構造

- 純関数 `buildSettlementShareModel(calculation, memberMap, include, powerCrystalNesoRate, t)` を `uiText.js` か新規 `shareImage.js` に置き、**描画データ(行の配列)を組み立てる部分をテスト可能に**する(canvas描画自体はスモークのみ)
- 数値は画面表示と同一ソース(`calculation` の値をそのまま整形)。**画面と画像で数字が食い違わないこと**が最重要
