## 2. A — UTC 統一

- **チャートの X 軸ラベル / ツールチップの時刻 / ヒートマップの列見出し**をすべて **UTC** に
- **曜日の併記は維持**(SH-11 の要望①)。ただし**曜日も UTC で算出**する
- **曜日名はロケール追随のまま**(`Intl` に `timeZone: "UTC"` を渡す。**ハードコード表を作らない**)
- **「UTC」であることが画面から分かること**。ツールチップの時刻に `UTC` を付す等
  (**計算条件ブロックは復活させない**。時刻表記の中に含める)
- **ローカル時刻の痕跡を残さない**(タイムゾーン検出・オフセット表示のコードは削除)

## 3. B — 装備一覧をアルファベット順

- 検索候補・一覧とも **`itemName` の昇順**
- **比較は `localeCompare`**(単純な `<` 比較にしない)
- **代表と alias が混在した候補リスト全体**でアルファベット順(グループごとに固まらせない)
- 既存の検索一致ロジック(代表名 + alias 名 + itemId)は**変えない**。**並びだけ**

## 4. C — ヒートマップの起点を木曜 UTC 00:00

- **行の順**: 木 → 金 → 土 → 日 → 月 → 火 → 水(**木曜が最上段**)
- **列の順**: **UTC 00:00 → 04 → 08 → 12 → 16 → 20**(00:00 が最左)
- ∴ **左上のセル = 木曜 UTC 00:00**
- **セルの中身(中央値の算出)は変えない**。**並べ替えだけ**
  — (d) で「並べ替え前後で各セルの値が一致する」ことを示すこと

## 5. 受け入れ基準

- **(a)** X軸・ツールチップ・ヒートマップ列がすべて **UTC**。**画面から UTC と判別できる**
- **(b)** 曜日が **UTC 基準**で併記され、**ロケールに追随**する(ja/en/zh-TW の実測を報告)
- **(c) ★統括の実測と一致**: `Arcane Umbra Staff` / `0→17` / 150日 で、
  **UTC 曜日別中央値が 木 +7.2% / 日 +6.7% / 水 −5.9% / 火 −5.5%、曜日間 13.9%**
  (統括が SH-11 前に測った UTC 基準の値。**データ進行分のドリフトは許容**、傾向と桁が一致すること)
- **(d) 値が変わらないこと**: ヒートマップの並べ替えは表示順のみで、
  **各(曜日,時間帯)セルの中央値と件数が並べ替え前と一致**する
- **(e)** 左上セルが **木曜 00:00 UTC**
- **(f)** 装備候補が **`localeCompare` の昇順**。実例(先頭5件と末尾5件)を報告
- **(g)** `npm run test` 全緑 / `npm run build` 成功 / **`server/` の差分ゼロ**
- **(h)** 6ロケールのキー数一致
- **(i)** SH-7〜SH-13 の性質維持(暫定点・統計除外・意味色・2桁表記・maxStar ガード・
  alias 検索・ナビ・テーマ・プリセット3種・削除済み表記が復活していないこと)
