# IMPL_PLAN_SH23 — 現在価格を公式 Open API(1分粒度)へ切り替え

前提: SH-22 完了(検収は別途)。**ユーザー指示 2026-08-05**:
> 最新価格を20分キャッシュにしていたが、これは公式APIを使えばリアルタイム取得できるはず。
> ただし負荷を考え、5分キャッシュにしたんだった。

## 0. 統括の実測 — ユーザーの認識が正しい

現行の現在価格は**無認証**の
`msu.io/maplestoryn/api/msn/dynamicpricing/enhance-price/latest` を使っており、
その `latestUpdatedAt` は **20分グリッド**でしか動かない(SH-14/SH-15 の観測)。

**ラッフルが使っている公式 Open API に、より新鮮な同等エンドポイントがある**:

```
GET https://openapi.msu.io/v1rc1/enhancement/items/{itemId}/dynamicprice
ヘッダ: Content-Type: application/json / x-nxopen-api-key: <KEY>
```

統括が実際に叩いた結果(`itemId=1382265`):

```json
"starforce": { "0": {
  "currentPrice":  { "startDate":"2026-08-05T11:53:00Z", "endDate":"2026-08-05T11:54:00Z",
                     "createDate":"2026-08-05T11:53:49Z",
                     "price":"378709985495000000000000", "step":"STEP_TYPE_CHANGE" },
  "previousPrice": { ... 11:52 の1分 ... } } }
```

- **価格は1分ごとに更新される**(`startDate`〜`endDate` が1分)
- **有効期間が明示されている**
- 星キーは **0..24 の25件**(旧 latest は 0..22 の23件)
- **単位は同じ**(÷1e18 → NESO)。**星インデックスの意味も同じ**

| star | Open API (NESO) | 旧 latest (NESO) | 比 |
|---|---|---|---|
| 0 | 378,668.70 | 379,287.92 | 0.9984 |
| 10 | 2,038,786.99 | 2,044,536.22 | 0.9972 |
| 17 | 3,670,296.06 | 3,683,773.28 | 0.9963 |

**差は鮮度だけ**(旧が最大20分古い)。

## 1. 変更内容

- **現在価格の取得先を公式 Open API に切り替える**
- **キャッシュは 5分**(ユーザー指定。負荷配慮)
- **履歴(`enhance-price/history`)は変更しない**(Open API に同等が無い)

## 2. ★秘密情報の扱い(絶対条件)

- **API キーは `MSU_OPEN_API_KEY` 環境変数からのみ読む**
- **リポジトリに値を書かない**(`.env`・fixture・テスト・ドキュメント・報告書すべて)
- **ログに出さない**(リクエストヘッダをそのままログしない)
- **ブラウザに渡さない**(`/sf-history/latest` の応答にキーを含めない。**サーバー内のみ**)
- ローカル開発の推奨先は **`C:\Users\<user>\.lulumi-tools\raffle-api.env`**(Git 外・既存)
- 本番は **`/etc/lulumi-tools/*.env`**(ラッフルと同じ流儀)

**★報告書にキー値を書かないこと。**

## 3. 実装

### 3-1 取得

- `fetch_latest.py` の上流を **`https://openapi.msu.io/v1rc1/enhancement/items/{itemId}/dynamicprice`** に
- ヘッダ `Content-Type: application/json` / `x-nxopen-api-key`
- **星の抽出**: `data.currentPrices.starforce` の各キー(**文字列キー**)を int 化し、
  `currentPrice.price` を **÷1e18 で NESO 化**(既存の換算と同じ)
- **0..24 が来ても、使うのは既存どおり必要な範囲だけ**。25件前提のハードコードをしない
- **`latestUpdatedAt` は `currentPrice.startDate`**(その価格がいつ時点のものか)を採用。
  **応答のフィールド集合は変えない**(契約テストが守っている)

### 3-2 キャッシュ

- **TTL 5分固定**(ユーザー指定)。SH-15 で入れた
  「上流スタンプから次回公開時刻を導出する」ロジックは**このエンドポイントには合わない**
  (1分粒度なので、導出すると毎分叩きに行く)ため、**単純な固定 TTL に戻す**
- **上限・下限のガードは維持**(誤設定で0秒や巨大値にならないこと)
- **single-flight を維持**
- 環境変数 `SF_HISTORY_LATEST_TTL_SECONDS`(既定 300)で調整可能に
- **レート制限**: 公式は既定 2 RPS。28装備 × 1回/5分 ≈ **0.09 RPS** なので余裕がある。
  **それでも single-flight を外さない**

### 3-3 ★キー未設定時のフォールバック

**`MSU_OPEN_API_KEY` が設定されていない場合は、従来の無認証エンドポイントにフォールバック**する。

- 本番へキーを配る前でも**画面が壊れない**ようにするため
- **どちらを使ったかをログに1行**出す(**キー値は出さない**)
- 応答の形は**どちらでも同じ**

## 5. 受け入れ基準

- **(a)** キーがある環境で、上流が **Open API** になる。
  `latestUpdatedAt` が**分単位**で進む(**5分キャッシュ越しに2回観測して報告**)
- **(b)** **単位と星インデックスが従来と一致**: 同一時刻に両エンドポイントを叩いて
  **比が 1.00 に近い**(鮮度差ぶんのみ)ことを実測して報告
- **(c) ★キー未設定時のフォールバック**が効く(環境変数を外して起動し、
  従来の値が返ることをテスト or 実測で示す)
- **(d) ★秘密情報**: キー値がリポジトリ・ログ・応答・報告書のどこにも出ない。
  **`git grep` で確認して報告**
- **(e) 契約テストが緑**(応答の形が変わっていない)
- **(f)** `pytest` 全緑(**オフライン**。実 API を叩くテストを書かない)
- **(g)** `npm run test` 全緑 / `npm run build` 成功(フロント無変更)
- **(h)** `/prices` の暫定点・4h テーブルのハッシュが不変
- **(i)** SH-7〜SH-22 の性質維持

## 6. 停止条件

1. **応答の形を変えないと実装できない**(契約テストが落ちる)
2. Open API の星キーの意味が従来と違うと分かった(**(b) の比が 1 から大きく外れる**)
3. **キーを設定しないとテストが通らない**構造になった(**テストはオフラインであること**)
4. §4 の「触らないもの」に触る必要が生じた / 新規依存が必要になった
