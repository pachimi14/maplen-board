## 2. B — チャートの8時間の穴を塞ぐ

### 2-1 原因(統括が実測)

```
now        2026-08-05 04:55 UTC
hourly最新  2026-08-05 00:00 UTC
4h 最新     2026-08-04 20:00 UTC   ← 00:00 バケットが未生成
暫定        2026-08-05 04:00 UTC
→ 20:00 と 04:00 の間に 8時間の穴
```

`00:00` バケットは **04:00 UTC に完成した**が、**集約を再実行した者がいない**ため
4h テーブルに入っていない。ローカルは timer が無いので常時、
**本番でもバケット完成から次のジョブ(:43)までの最大43分間**同じ穴が開く。

### 2-2 直し方 — **保存せず、API が導出して返す**

**規約を単純化する**:

> **4h テーブルに在るもの = 確定(実線・統計に入る)**
> **在らず hourly から導出できるもの = 暫定(破線・統計から除外)**

∴ `prices` は、4h テーブルの最新より後ろについて、**hourly から導出できるバケットを
`provisional: true` で返す**。これで
- **完成済みだが未保存のバケット**(今回の 00:00)
- **進行中のバケット**(04:00)

の**両方が同じ規則で埋まり、穴が消える**。

- **4h テーブルには一切書かない**(SH-3 の決定性・SH-7 の受け入れ基準 (a) を維持)
- 進行中バケットの値の出どころは**従来どおり `latest` の共有キャッシュ**(SH-7 §3-1)。
  **完成済み未保存バケットは hourly から**(区間内の最後の `end_price`)
- **暫定点は複数になりうる**。`provisionalDate` は**最も新しい暫定点**を指すものとし、
  意味が変わることを README に書く(既存の意味を黙って変えない)

### 2-3 統計・表示

- **暫定点は引き続き統計に入れない**(平均・高値・安値・パーセンタイル・ヒートマップ)
- 破線区間が2区間になりうる。**中抜きマーカーは各暫定点に付ける**

## 3. C — プリセット

`STAR_RANGE_PRESETS` を **`0→17` / `0→21` / `0→22` の3つだけ**にする。

## 4. 受け入れ基準

- **(a)** §1 の5項目が**画面に出ない**。計算条件セクションごと消えている
- **(b) ★穴が塞がる**: 現在の DB 状態(hourly 最新 `2026-08-05T00:00Z` / 4h 最新 `2026-08-04T20:00Z`)で
  `prices` を叩き、**`20:00 → 00:00 → 04:00` と 4時間刻みで連続**すること。
  **確定点と暫定点の内訳(何点が provisional か)を報告**
- **(c) ★4h テーブル不変**: 本スライスの前後で**行数とハッシュが一致**
- **(d) 統計不変**: 暫定点が増えても平均・高値・安値・パーセンタイル・ヒートマップの値が
  **確定点のみのときと1ビットも変わらない**
- **(e)** プリセットが **3つだけ**。☆20 装備で `0→21` `0→22` が disabled
- **(f)** 6ロケールのキー数が**揃っている**(削除後)。未使用キーが残っていない
- **(g)** `npm run test` 全緑 / `npm run build` 成功 / **`server/` は B のためだけに変更**
  (`aggregate.py` / `schema.sql` / `scripts/*` は**触らない**)
- **(h)** SH-7〜SH-12 の性質維持(`asOf` 表示・意味色・2桁表記・maxStar ガード・
  alias 検索・ナビ・テーマ・ローカル時刻)
