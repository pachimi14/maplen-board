## 0. ★現状(統括が実測)

**数字は全言語共通の ISO、曜日だけ各言語**という中途半端な混在:

```
現状:  2026-08-18 04:55 UTC (Tue)      ← 全言語で同じ並び
```

各地域の標準表記(`Intl` 実測):

| 言語 | 標準表記 | 現状との違い |
|---|---|---|
| en | `Tue, 08/18/2026, 04:55` | **月/日/年** |
| ja | `2026/08/18(火) 04:55` | 区切りが `/`、曜日が括弧内 |
| zh-TW | `2026/08/18（週二）04:55` | 同上 |
| th | `อ. 18/08/2569` | **日/月/年 + 仏暦**(2026→2569) |
| vi | `Th 3, 18/08/2026` | **日/月/年** |
| es | `mar, 18/08/2026` | **日/月/年** |

**`05/06` のような日付は地域によって「5月6日」「6月5日」に割れる** = 実害がある。

## 1. 方針

**`Intl.DateTimeFormat` に各地域の表記を委ねる。**

- **★タイは仏暦のまま**(2569)。**現地で正しい表記**であり、ユーザー裁定済み。
  **西暦に固定しない**
- **12時間制 / 24時間制も各地域の慣習に従う**(`hour12` を強制しない)。
  **どう出るかを全ロケール実測して報告**すること
- **★UTC の明示は維持**(SH-14 の決定)。**どのゾーンの時刻か分からない表示にしない**
- **曜日は引き続き表示**(ヒートマップの行・チャートの軸で使っている)

## 2. ★表示だけを変える(最重要)

**計算・集計・キー・並び順に使われる値を1ビットも変えない。**

- **ヒートマップのセル割り当ては UTC 基準のまま**(SH-14/SH-18/SH-29)。
  **`buildWeekdayHeatmap` に触らない**
- **`price_at` / バケットの境界 / API の応答**は**一切変えない**
- **内部で日付文字列をキーや比較に使っている箇所があれば、そこは ISO のまま**にする。
  **表示用の整形だけを差し替える**
- **`priceGapFill` / `chartColumns` / `series.js` の判定に使う日付**は変えない

**この分離ができない箇所を見つけたら、停止して報告すること。**
