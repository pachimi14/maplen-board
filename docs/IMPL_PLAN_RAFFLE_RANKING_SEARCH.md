# IMPL_PLAN — キャラ検索をランキング先行(予測変換)+API後段へ

> 状態: 統括承認済み(ユーザー指示 2026-08-14 = LULU-115)
> ブランチ: `raffle/ranking-first-search`(origin/main 起点・コミットする・push しない)

## 0. 統括が実コードで確認した前提

- **ランキングデータは raffle ページでも既に読込済み**: `BoardProvider` が全ルートで `data/v2/rankings.json` を無条件 fetch し、raffle ルートもその配下。よって `useBoard().characters` を使えば**追加のネットワーク取得はゼロ**
- ランキング全 8,428 件が **`CHAR` 形式 assetKey・worldId・level・job・imageUrl を保持**(raffle の既存 assetKey 検証 `^CHAR[A-Za-z0-9_-]{4,124}$` に 8428/8428 適合)。level は 225〜262
- **worldId の表現が両ソースで異なる**: ランキング=世界名(`Ain`/`Fang`/`Errai`)、公式API=数値文字列(例 `"2"`)。現行 `addMember` の world 一致チェックは単純比較のため、**混在すると正当なPTが誤って「別ワールド」エラーで弾かれる**(本計画で対処)

## 1. スコープ

### S1. ランキング先行の予測変換候補(APIを叩かない)

- 新規純関数 `exp_ranking/web/src/raffle/domain/rankingSearch.js`
  - `searchRankingCharacters(characters, query, { limit = 10 })`
  - 正規化: `trim` + casefold。**1文字から発火**(部分一致)
  - 並び: ①完全一致 ②前方一致 ③部分一致、各グループ内は `rank` 昇順。上限 `limit`
  - 出力形: 既存候補と同形 `{ assetKey, displayName, level, jobName, worldId, imageUrl, source: "ranking" }`(`characterAssetKey` 未保持・非CHAR形式は除外)
- UI(`RaffleCalculatorRoot.jsx`): 入力の変化に応じて候補を即時表示。**候補クリックで PT 追加(API 呼び出しゼロ)**
- 候補行に「ランキング」バッジと Lv/職/ワールドを表示
- ランキング未ロード/失敗時: 候補欄に読込中/利用不可の文言(API 検索は使える旨を併記)

### S2. 検索ボタン(公式API)は後段として維持 + 停止時アナウンス

- ボタン押下時は従来どおり完全一致 API 検索(Lv225未満・ランキング未掲載を拾うため)
- 結果はランキング候補と**同一リストへ統合**し、`assetKey` で重複排除(API 由来を上位、バッジで区別)
- **API 応答なし/失敗時**: 既存のローカライズ済みエラーに加え、新規アナウンスを表示
  「公式APIに接続できません。Lv225以上のランキング掲載キャラは上の候補から追加できます。Lv225未満のキャラはAPI復旧後に追加してください。」
- API 停止中でもランキング候補からの追加は**成功する**こと(ブロックしない)

### S3'. ワールド一致ブロックの撤去(ユーザー裁定 2026-08-14 により S3 を差し替え)

当初は worldId 表現差(ランキング=世界名 / API=数値)を吸収する `worldSource` タグ付けを計画したが、ユーザー指摘を受けて統括が再調査した結果、**ワールド一致チェックは仕様書・DECISION_LOG のいずれにも存在しない未記録のガード**であり、`worldId` は「①当該ブロック ②localStorage 保存 ③表示」にしか使われていない(APIリクエスト・討伐マッチング・分配計算のいずれにも不関与)ことを確認した。送金はウォレット間でワールド非依存、別PT討伐の合算も許可済み(LULU-078/096)のため、ブロックの根拠がない。守る価値のないガードのために同期面(2つの世界ID語彙)を増やすのは本末転倒。

- `addMember` の**ワールド不一致チェックを削除**(`worldSource` 等の追加実装は行わない)
- `worldId` は**表示用として保持**(保存形式は不変=後方互換)
- 表示は**読める世界名のときのみ**(数値IDは利用者に意味がないため非表示)
- i18n `raffle.worldMismatch` を6ロケールから削除
- 誤追加の検出は既存の「ラッフル履歴: なし(当選0)」表示に委ねる(機械的ブロックより情報提示)

## 3. 受け入れ基準(数値)

1. 8,428 件相当の合成データで、部分一致クエリに対し候補が **10件以内**・完全一致が先頭に来ることをテスト固定
2. **候補からの追加で `fetch` 呼び出し 0 回**(spy で検証)
3. API 失敗をモックした状態で、①アナウンス文言が表示され ②ランキング候補からの追加が成功する、をテスト固定
4. ランキング由来(world=`Ain`)+ API 由来(world=数値)を混在させても**エラーにならず両方 PT に追加できる**
5. 既存 localStorage の PT を読み込んでも例外なく動作(保存形式不変)
6. web テスト全緑・build 成功・6ロケールパリティ(新規キーは6言語同時)
