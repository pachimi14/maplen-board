# IMPL_PLAN_SH16 — 足の点は足の時刻 / 現在値は自分の時刻に独立して置く

前提: SH-15 完了・統括検収済(`8a994c1`)。**ユーザー実機レビュー起点**。

## 0. 現状の問題(統括が特定)

ユーザー報告:
> 実線が 8/4 20:00 で、その次が**時間無し**、最新が 8/5 6:20 になっている。
> ここを `8/4 20:00` → `8/5 0:00` → `8/5 4:00` → 破線で `8/5 6:20` にしたい。

### 0-1 「時間無し」の原因

`SfHistoryChart.jsx:21`:
```js
timeLabel = point.provisional ? (point.asOf ? formatTooltipDate(point.asOf) : null) : formatTooltipDate(point.date)
```

SH-8 で「**暫定点は足の境界でなく取得時刻を出す**」と決めた。
ところが SH-13 で足した「**完成済みだが未保存**」の暫定点には **`asOf` が無い**ため、
**時刻行が丸ごと消える**。

### 0-2 位置と時刻の食い違い

進行中バケットの点は **位置が `04:00`(バケット開始)なのに、表示時刻は `06:20`(`asOf`)**。
**同じ点が2つの時刻を主張している。**

## 1. 変更後のモデル(ユーザー裁定)

| 種別 | x 位置 | 時刻表示 | 線 | 統計 |
|---|---|---|---|---|
| **確定バケット**(4h テーブル在) | 足の開始時刻 | **足の時刻** | 実線 | **入る** |
| **暫定バケット**(hourly から導出) | 足の開始時刻 | **足の時刻** | 破線 | 入らない |
| **現在値**(`latest` 由来) | **`asOf` の時刻そのもの** | **`asOf`** | 破線 | 入らない |

**要点は2つ**:
1. **足の点は必ず足の時刻を出す**(`asOf` が無いから時刻を消す、をやめる)
2. **現在値は足に混ぜず、自分の時刻の位置に独立した点として置く**

∴ 例の並びは `8/4 20:00`(実線)→ `8/5 00:00` → `8/5 04:00` → **`8/5 06:20`**(破線の最終点)。

> **SH-8 の意図は損なわれない。** SH-8 は「暫定点が古い時刻を主張して古く見える」のを嫌った。
> 本スライスは**現在値を本当の時刻の位置に置く**ので、その懸念はより正確に解消される。
> **SH-8 の決定の精緻化として記録する**(反転ではない)。

## 3. サーバー側

`/prices` の `points` を次の3種で構成する:

```json
{ "date": "...", "prices": [...] }                                  // 確定
{ "date": "...", "prices": [...], "provisional": true }             // 暫定バケット(hourly由来)
{ "date": "<asOf>", "prices": [...], "provisional": true, "current": true, "asOf": "<asOf>" }  // 現在値
```

- **現在値の点の `date` を `asOf` にする**(位置と時刻を一致させる)
- **`current: true` で識別**できるようにする(フロントが「足でない点」と分かるように)
- **進行中バケットに現在値を差し込むのをやめる**。
  進行中バケットに hourly があれば**暫定バケットとして**出す(足の時刻で)
- `provisionalDate` は**最も新しい暫定点**を指す定義のまま(SH-13)。README を実態に合わせる
- **上流失敗時は現在値の点を出さない**(SH-13 の劣化方向を維持。`prices` は 200)
- **4h テーブルには一切書かない**

## 4. フロント側

- **時刻表示は常に `point.date` を使う**(`asOf` の有無で分岐しない)。
  現在値の点は `date === asOf` なので**自動的に正しい時刻**になる
- 現在値の点であることが分かる表示(任意。**新しい文言を増やすなら6ロケール同時**)
- **破線・中抜きは全暫定点に適用**(現在値の点を含む)
- **統計・ヒートマップは `provisional` を除外**(現在値の点も `provisional: true` なので自動的に除外)

## 5. 受け入れ基準

- **(a)** `/prices` の末尾が **`20:00`(確定)→ `00:00`(暫定)→ `04:00`(暫定)→ `<asOf>`(現在値)** の順で、
  **`current: true` の点がちょうど1つ**(取得できたとき)
- **(b)** 現在値の点の **`date` が `asOf` と一致**する
- **(c) ★時刻が全点で出る**: どの点にも時刻表示があり、**「時間無し」の点が存在しない**
- **(d) ★位置と時刻が一致**: 現在値の点の x 位置が `asOf` の時刻
- **(e) 統計不変**: 確定点のみのときと、平均・高値・安値・現在の位置・**ヒートマップ**が
  **1ビットも変わらない**。現在値の点を極端な値に改竄しても不変
- **(f) 4h テーブル不変**: 行数・ハッシュが `577792 / 707de4ad3f05de93` のまま
- **(g)** 上流失敗時に現在値の点が出ず、`prices` が **200** で確定履歴を返す
- **(h)** `pytest` 全緑(オフライン)/ `npm run test` 全緑 / `npm run build` 成功
- **(i)** 6ロケールのキー数一致
- **(j)** SH-7〜SH-15 の性質維持(UTC・意味色・2桁表記・プリセット3種・
  パーセンタイル文言・20分スタンプ・maxStar ガード・alias 検索・ナビ・テーマ)
