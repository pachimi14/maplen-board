## 1. D — 価格の丸め(★最も実害がある)

### 1-1 現状の欠陥

☆1〜10 が **`0 NESO`** と表示されている。**実際の値は `0.000001` 前後**。

**これは単なる見た目の問題ではない。** 価格形成の進み具合は
**`0.000001`(手つかず)〜`0.000441`(進行中)という小数部だけに現れる**。
そこを丸めて潰すと、**このページの存在意義である「どこまで進んだか」が読めなくなる**。

### 1-2 ★丸めなくてよい根拠(統括の実測)

上流の価格は **`1e12`(= `0.000001` NESO)の整数倍**である。実測:

```
235000000000000              -> 0.000235        (235 x 1e12)
96058335091000000000000      -> 96,058.335091   (6桁でちょうど収まる)
1132506562014000000000000    -> 1,132,506.562014
```

∴ **小数第6位まで出せば、大小どの値でも情報が1ビットも落ちない。**
7桁目以降は**常に 0** なので、出す必要も無い。

### 1-3 実装

- **小数第6位まで表示し、末尾の 0 は落とす**(`0.000001` / `1,132,506.562014` / `23,758.94`)
- **整数部は従来どおり3桁区切り**
- **既存 `formatCompactNeso` を変更しない**(チャート側は2桁丸めのまま。**SH-32 の応答は full precision**)
- **`0` と表示してよいのは、値が本当に 0 のときだけ**

## 2. C — 用語(★ユーザー裁定: 案A)

**`DISCOVERY` は内部語ではなく `price discovery`(価格発見)という市場用語**で、
「取引が積み重なって値段が定まっていく過程」を指す。**その意味を素直に訳す**。

| 状態 | 日本語 | 英語 |
|---|---|---|
| `STEP_TYPE_DISCOVERY` | **価格形成中** | **Forming** |
| `STEP_TYPE_CHANGE` | **形成済み** | **Settled** |

- **UI から `DISCOVERY` / `ボーナス` の語を完全に消す**(6ロケールとも)
- **★「お得」「特典」の含意を持たせない**。安いのは事実だが、
  それは**まだ市場が値段を決めきれていない**からであって、運営が配っている特典ではない。
  **`ボーナス` / `セール` / `お得` / `先行価格` 系の語を使わない**
- **コード内部・DB・API の値は `STEP_TYPE_DISCOVERY` のまま**(上流の語なので変えない)。
  **変えるのは表示だけ**
- ページ見出しと説明文も書き換える(現在「DISCOVERY(ボーナス期間)」)
- **1行で「なぜ価格がほぼ 0 なのか」が分かる説明**を入れる
  (例: 「取引がまだ少なく、価格が定まっていない状態です」)。**推測を書かない**

## 4. B — 検索候補をグループ単位に

**15件 → 3件**。API は既に**代表 + `aliases`** の形で返している(`/sf-history/discovery/equipment`)ので、
**表示の畳み込みだけの問題**。

- 1候補 = **1グループ**。**代表名**を主に出す
- **同じグループの職業違い5種を、その候補の中に小さく併記**する
  (例: `Knight / Mage / Archer / Thief / Pirate`)。**別候補として並べない**
- **★どの職業名でも引ける性質は維持**(SH-32 (g-1))。
  `Arcane Umbra Mage Hat` と打ったら、**Hat のグループが1件出る**
- **itemId でも引ける**(15件のいずれの itemId でも、そのグループが出る)
- **代表名が検索語と違っても、なぜその候補が出たのか分かる**ようにする
  (例: 一致した alias 名を候補内で示す)。**黙って別名を出さない**
