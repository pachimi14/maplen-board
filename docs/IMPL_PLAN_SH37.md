## 1. B / C の原因(統括が実測で確定)

**バグではなく、帯ごとに履歴の開始日が違うため。**

```
Hat   ☆11〜18  8/17〜8/18 から履歴あり
      ☆19     8/20 00:00Z から      ← 0→22 の律速
Suit  ☆11〜18  8/9〜8/13 から履歴あり
      ☆1〜10   8/21 04:00Z から      ← 0→ の律速(本日)
```

チャートは**必要な全帯が揃った足しか描けない**ので、1本でも遅い帯があると、そこまで線が出ない。
上流は**価格形成中の帯の履歴を返さない**(SH-32 F2)ので、**遡って取得することはできない**。

## 2. ★方針(ユーザー裁定)

> 価格形成が最も早かった行に合わせられないか。**価格未形成だった行は 0…1 にするなどの対応でいい。**

**その期間、その帯は実際にほぼ無料だった**ので、下限値で埋めるのは**捏造ではなく事実に近い扱い**。

### 2-1 統括の実測(埋めた場合の Hat 0→22)

```
08-17 12:00   0.208B    欠け ☆11,13,14,15,18,19
08-18 04:00   1.489B    欠け ☆19
08-19 20:00   1.065B    欠け ☆19
08-20 00:00   1.650B    欠けなし   ← ☆19 の価格形成が終わった段差
08-21 08:00   1.474B    欠けなし
```

**8/20 の 1.06B → 1.65B の段差は事実**であり、**「いつ高くなったか」が読める**ようになる。
線が途中から始まるより有用。

### 2-2 精度について(隠さない)

埋める値は**下限**であって、その時点の実価格ではない。
ただし形成中の帯の実価格はせいぜい数千 NESO、形成後の ☆19 は約290万 NESO なので、
**差は 0.05% 未満**(段差 約0.6B に対して無視できる)。
∴ **埋めた区間の値は厳密には下限**である。**この事実を注記で示す**(§4)。

## 3. 実装(B / C)

**4時間足の各点について、値が無い帯を下限値で埋めてから Expected を計算する。**

- **★埋めるのは「先頭の欠け」だけ**にすること。
  ある帯の**最初の履歴点より前**の区間のみ埋める。
  **履歴が始まったあとの中抜け(欠測)は埋めない** — それは価格形成ではなく取得漏れであり、
  **性質が違う**。埋めると欠測を隠すことになる
- **下限値は 1e-6 NESO**(上流が返す最小単位。SH-34 で確認済み)
- **埋めた帯・埋めた区間を、点ごとに識別できる形で持つ**(§4 の注記に必要)
- **全帯に履歴がある装備の計算を1ビットも変えない**(既存31装備の回帰ゼロ)
- **SH-36 の「現在形成中の帯は現在価格で埋める」性質は維持**する。
  **本件は「過去の欠け」の話で、別の層**。両方が同時に効くこと

## 4. 注記(A/B/C 共通の原則)

- **埋めた区間があることが分かる**ようにする。**段差の理由を読者が誤解しないため**
- **事実だけを書く**(例: `☆19 は 08/20 まで価格形成中でした`)。
  **「概算」「不正確」「安い」「お得」などの評価語を使わない**
- **埋めた帯が無い装備・期間では出さない**
- SH-36 の「いま形成中の帯」の注記とは**別の情報**。**両方出る場合に混ざらない**こと
