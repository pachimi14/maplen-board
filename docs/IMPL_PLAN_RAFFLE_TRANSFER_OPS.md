## C1. PTメンバー順の正規化(LULU-104)

背景: 分配は入力順依存(端数+1の配分先・送金2ポインタのペア順)。入力し直しや人による順序差で「誰が誰に送る」が変わる。

- 純関数 `sortPartyMembers(members)`: **casefold したキャラ名の Unicode コードポイント降順**、同名は assetKey 昇順で決着。`localeCompare` 禁止(端末非依存の同一結果が目的)
- 適用箇所: ①PTメンバー一覧の表示 ②ジョブリクエストの characters 構築(=memberId 採番) ③以降の全下流(結果タブ・カード・精算)は自動追随
- 保存形式(localStorage)は不変(表示・計算時に正規化)
- 文言: 「余り（PT順に+1）」→「**余り（キャラ名順に+1）**」6ロケール
- テスト: 同一メンバー集合を異なる入力順で与えても settlement 出力(余り配分先・transfers)が完全一致することを固定

## C2. 送金通知コピー(LULU-103)

背景: 現在は精算表を見ながら手書きで Discord 通知している。1ボタンで通知テキストをコピーしたい。形式(ユーザー指定・キャラ名でよい):

```
SHIVA → pachimi 68,720,465 NESO
0xEE158FbBF3507A4a7e42C112e49725db4875a5b9
```

(送金1件=2行: 「送り主 → 受取人 金額 NESO」+受取人のウォレット。件間は空行)

### サーバー(raffle-api)— LULU-069 の一部改定(ユーザー裁定済み)

- ジョブ応答に **リクエストされたPTメンバー自身の owner wallet** を含める: 各キャラ処理で解決済みの `wallet_address` を `characters`/メンバー単位の応答(例: レスポンスに `memberWallets: {memberId: "0x..."}`)として返す。**wallet override 使用時はその値**。未解決(wallet_not_available)のメンバーは含めない
- **ログに wallet を出さない方針は不変**。キャッシュにも保存しない(既存どおり)
- tests 追随(48+)

### Web

- `contract.js`: `memberWallets` の受け入れ(形式検証: `0x[0-9a-fA-F]{40}` のみ通す・不正は捨てて警告なし欠落扱い)
- 「実際の送金」セクションに「**送金通知をコピー**」ボタン(新キー・6ロケール)。純関数 `buildTransferNotificationText(transfers, memberMap, memberWallets)` をテスト可能に分離
  - 受取人のウォレット不明時: 2行目を「(ウォレット未取得)」(新キー)にし、ボタン付近に注意書きを出す(黙って欠落させない)
  - コピー: `navigator.clipboard.writeText` → 失敗時は textarea+`document.execCommand('copy')` フォールバック(**http環境でも動作**)。結果ステータス表示は画像コピーと同様の様式
- 数値書式は画面と同一(3桁区切り)

## C3. 送金行レイアウト変更(画面+共有画像、ユーザー追加指示)

背景: 「SHIVA → pachimi」と金額が離れていて"誰が誰にいくら"が一目で入らない。右側にウォレットを載せれば隙間が詰まり、送金時の宛先検証もできる。

- **ブラウザ(`SettlementResult.jsx`)の送金行**: 左に `送り主 → 受取人 金額 NESO` を**詰めて**配置(金額は名前の直後・太字)、**右端に受取人のウォレットアドレス全文**(等幅・小さめ・コピー阻害しない選択可能テキスト)。wallet 未取得は「(ウォレット未取得)」表示
- **共有画像(`shareImage.js`)の送金行**: 同構成(左=名前+金額を近接、右=ウォレット全文右寄せ。フォントはウォレットのみ小さめ可)。行高・帯は現行踏襲
- ウォレットを画像に含めることは**ユーザー明示指示**(旧仕様の「コピー結果へ wallet を含めない」は本件で置換)

## 受け入れ基準

1. 同一メンバー集合・異なる入力順で、余り配分先と送金一覧が**完全一致**(テスト固定)
2. 通知テキストが指定形式と一致(複数件・空行区切り・ウォレット40hex)をテスト固定。ウォレット欠落メンバーの明示表示
3. サーバー: wallet がレスポンスに含まれ、**ログには出ない**(既存のログ方針テストがあれば追随)
4. web 全テスト緑・raffle-api pytest 緑・build 成功・6ロケールパリティ
5. 表示メンバー順=計算順=名前降順の一致
