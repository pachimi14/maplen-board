## 2. ① ローカル時刻表示

**データは UTC のまま。表示だけローカルに変換する。**

- 対象: **チャートの X 軸ラベル / ツールチップの時刻 / 計算条件の「履歴の最終更新」「現在価格の取得時刻」**
- **曜日を併記する**(ユーザー要望①)。例 `08/04 (月)` / `2026-08-04 20:00 (月)`
- **曜日名は `Intl.DateTimeFormat` に現在のロケールを渡して得る**。
  **7言語分の曜日名をハードコードしない**(6ロケール × 7曜日を手で持つと必ず腐る)
- **★タイムゾーンを画面に明示する**(計算条件に1行)。
  例「表示時刻: お使いの端末のタイムゾーン(UTC+9)」。
  **どのタイムゾーンで見ているか分からない画面にしない**(判断原則#2)
- **4時間足の境界は UTC 基準**なので、ローカルでは端数がありうる
  (JST なら 09/13/17/21/01/05 時)。**これを丸めたり詰めたりしない**。実際の時刻をそのまま出す

## 3. ② 曜日 × 時間帯ヒートマップ

### 3-1 集計(`weekdayStats.js`・純粋関数)

- 入力 = **確定点のみの Expected 系列**(`buildExpectedSeries` の出力から `provisional` を除く)
- 縦 = 曜日7(**ローカル**)/ 横 = 4時間枠6(**ローカルのバケット開始時刻**)= **42セル**
- 各セルの代表値 = **中央値**(平均ではない。スパイクに引きずられないため)
- 各セルに **n(標本数)** を持たせる

### 3-2 対象期間 — **常に取得できている全期間(約150日)**

**期間タブ(7/30/90/150日)に連動させない。** 理由:
- ヒートマップが答えるのは「**構造的にどの曜日・時間帯が安いか**」であり、直近の値動きではない
- 7日を選ぶと **1セル n=1** になり、**統計として無意味になる**(退化状態を作らない)

**「過去150日全体の傾向」であることをラベルで明示**すること。
> 期間連動が欲しくなったら別スライス。**未決 U8 として設計書に残す**。

### 3-3 表示

- 7行 × 6列。セルは**中央値で色分け**(安い=冷色 / 高い=暖色 等、テーマ変数を使う)
- **ホバーで実値と n を表示**
- **最安セル・最高セルを視覚的に示す**
- **断定的な推薦をしない**(設計 §11)。「今買え」「この曜日にやれ」とは書かない。
  **中央値と n を出し、判断はユーザーに委ねる**(GS-006 意思決定支援ツール)
- **n が少ないセルは視覚的に弱める**(例 n<5)。数字だけ出して過信させない
- 装備・星範囲を変えたら**再計算される**(Expected 依存なので当然)

### 3-4 性能

42セル × 中央値 = 900点の走査1回。**実測32msの Expected 計算に対して無視できる**。
それでも **(g) で実測値を報告**すること。

## 4. 受け入れ基準

- **(a)** チャートの X 軸・ツールチップ・計算条件の時刻が**ローカル時刻**になり、**曜日が併記**される
- **(b)** 曜日名が**ロケールに追随**する(ja/en/zh-TW で切り替えて実測を報告。`Intl` 使用)
- **(c)** **タイムゾーンが画面に明示**されている
- **(d)** ヒートマップが **7×6=42セル**。各セルに中央値と n。**n の合計 = 確定点の総数**(取りこぼしゼロ)
- **(e)** **統括の実測と一致**: `Arcane Umbra Staff` / `0→17` / 150日 で、
  UTC 基準に直したときの曜日別中央値が §0 の表と一致する(**曜日間 13.9%**)。
  ローカル基準の値も報告する
- **(f)** 暫定点がヒートマップに**入らない**(SH-7 の規約)。入れた場合と数値が変わることを示す
- **(g)** ヒートマップ再計算の所要時間(ms)。**期間タブを変えてもヒートマップは変わらない**ことを確認
- **(h)** `npm run test` 全緑 / `npm run build` 成功 / **`server/` の差分ゼロ**
- **(i)** 6ロケールのキー数一致
- **(j)** SH-7〜SH-10 の性質維持(暫定点1つ・統計に暫定なし・`asOf`・maxStar ガード・alias 検索・
  ナビ3リンク・テーマ)

## 5. 停止条件

1. `server/` を変えないとローカル時刻にできない
2. 曜日名のロケール追随が `Intl` で実現できない
3. (e) が統括の実測と合わない(**集計の解釈がずれている**=止めて数値を添えて報告)
4. §1 の「触らないもの」に触る必要が生じた / 新規依存が必要になった
5. ヒートマップ再計算が **200ms** を超える
