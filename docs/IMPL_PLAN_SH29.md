## 1. A — チャートの時刻は2重表示

ツールチップ・軸の時刻を **UTC を主、ローカルを従**として併記する。

```
2026-08-05 12:00 UTC
2026-08-05 21:00 (JST)      ← 小さく下に
```

- **UTC 表記は SH-14 の決定なので維持**(主)
- ローカルは**閲覧者の端末のタイムゾーン**。**オフセットまたはゾーン名を明示**する
  (`(JST)` / `(UTC+9)` のいずれか。**どのゾーンで見ているか分からない表示にしない**)
- **足のラベルは終了時刻のまま**(SH-18)。**進行中の足は現在時刻のまま**(SH-17)
- 軸ラベルは**場所が狭いので UTC のみでよい**。**ツールチップは必ず2重**
  (実装担当が軸も2重にできると判断するなら可。**判断を報告に書くこと**)

## 2. B — ヒートマップの列見出しをローカル時刻に

**★集計(どのセルに入るか)は UTC 基準のまま変えない。**表示ラベルだけローカルにする。

```
現在: 00:00  04:00  08:00  12:00  16:00  20:00   (UTC)
JST : 09:00  13:00  17:00  21:00  01:00  05:00   ← 同じ列・同じ中身
```

- ユーザーの言葉:「**JSTなら9:00を左上のUTC0:00のところに表示する**」
- **列の順序・セルの中身・行(曜日)の割り当ては1ビットも変えない**
- **行の曜日ラベルは UTC 基準のまま**(木曜起点。SH-14/SH-18)

### 2-1 ★正直さの要求

UTC からのオフセットが大きいゾーンでは、**列が示すローカル時刻の「日」が行の曜日(UTC)とずれる**。
∴ **ヒートマップにも UTC を併記する**(列見出しの下に小さく UTC、または見出しに「UTC基準」の注記)。
**どちらを見ているか分からない表を出さない。**具体的な形は実装担当の裁量でよいが、
**ローカルだけを出して UTC を消さない**こと。

## 3. C — 期間に 14日を追加

`PERIOD_KEYS` に `"14D"` を足す(`7D / 14D / 30D / 90D / 150D`)。
`PERIOD_DAYS["14D"] = 14`。**既定は 30D のまま**(SH-27)。

## 4. D — ヒートマップを期間タブに連動(★決定の反転)

**SH-11 §3-2 の「ヒートマップは期間タブに連動しない(常に150日)」を反転する。**

**ユーザーの理由**:
> 先週はどうだったか?という直近の生データが見れた方が良い。150日が見たいなら150日を選択すればいい。

**統括の同意**: タブは**ユーザーが見たい期間の意思表示**であり、それを無視して別の期間の集計を出すのは
**約束と請求の不一致**。性能は理由にならない(**実測 0.5ms**)。

### 4-1 ★標本数が減ることへの手当て

統括の実測(1装備・0→22):

```
期間    確定点   1セルの n    空セル
7D        41    0〜1          1個
14D       83    1〜2          0
30D      179    4〜5          0
90D      539   12〜13         0
150D     898   21〜22         0
```

**7D では n が 0〜1**。「中央値」と称して**1点をそのまま出す**ことになる。

∴ **1行の注記で、選択中の期間における1セルあたりの標本数を示す**。
例: 「この期間では1セルあたり約1点です」

- **42個の `n=` は復活させない**(SH-13 でユーザーが消した判断を尊重する)
- **「中央値」という語が嘘にならない程度の情報**を、**1行**で足す
- 既存の注記「過去150日全体の傾向(期間タブとは連動しません)」は**実態に合わせて書き換える**
- **空セル(n=0)は「データなし」表示**(既存の `heatmap.noData` を使う)

## 6. 受け入れ基準

- **(a)** チャートのツールチップが **UTC + ローカルの2重表示**。**ゾーンが明示**されている
- **(b) ★ヒートマップの列がローカル時刻**。JST で **左上が `09:00`**(= UTC 00:00 の列)
- **(c) ★セルの中身が不変**: 列見出しをローカルにしても、
  **各セルの中央値と n が SH-18 検収時と同じ規則で決まる**こと。
  具体的には **`[木][先頭列]` が「UTC 木曜 00:00 の足」を集めたセルのまま**であることを示す
- **(d)** ヒートマップにも **UTC が併記**されている(§2-1)
- **(e)** 期間タブが **7 / 14 / 30 / 90 / 150 日**。既定は **30日**
- **(f) ★連動**: 期間を変えるとヒートマップの n が変わる。
  **統括の実測値と一致**すること:
  `7D → n 0〜1・空セル1` / `14D → 1〜2` / `30D → 4〜5` / `90D → 12〜13` / `150D → 21〜22`
- **(g)** 標本数の注記が1行あり、**選択中の期間に応じて変わる**
- **(h)** `npm run test` 全緑 / `npm run build` 成功 / **`server/` の差分ゼロ**
- **(i)** 6ロケールのキー数一致
- **(j)** SH-7〜SH-28 の性質維持(暫定点・破線1点・意味色・2桁表記・ID非表示・初期装備 など)
