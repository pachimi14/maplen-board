# IMPL_PLAN — 追加報酬入力(+ボタンで任意行を追加)

> 状態: 統括承認済み(ユーザー指示 2026-08-27)
> ブランチ: `raffle/extra-reward`(origin/main 起点・コミットする・push しない)
> **Web のみ**(サーバー変更なし=VPS作業不要・`CLASSIFICATION_VERSION` 変更なし)

## 0. 背景(統括が実計算で確定)

実運用で「メイン6人固定・4人PT+別6人PT+キャリー」という編成が発生し、**キャリー報酬(他5人から10%ずつ送金されたNESO)を6人で分配したい**が入力欄が無い。

ユーザーは「前回持ち越し欄に入れて、誤入力チェックを外せば解決」と提案したが、**統括が実際に計算して否定**した:

| 入力(6人・各当選6,000万・m3がキャリー報酬6,000万) | 結果 |
|---|---|
| m3 に **−60,000,000** だけ(チェック無効時) | **送金0件**・m3の次回持ち越しに −60,000,000 が残るだけ |
| m3 に **+60,000,000** だけ(チェック無効時) | **送金0件**・m3の次回持ち越しに +60,000,000 が残るだけ |
| m3=−60,000,000 かつ他5人=各+12,000,000 | 送金5件・各12,000,000(正しいが入力6箇所+手計算が必要) |

**理由**: 持ち越し欄が動かすのは「残高」であり、残高は必ず相手方とセットで動く。片側だけ入れても送金の相手が存在せず、その額は次週へ繰り越されるだけ。**±0チェックを外すと「送金0件の誤った結果」が正常な顔で出る**ため、チェック撤去は解決にならない(=撤去しない)。

**正しい解**: キャリー報酬は「分け合う元手」なので、残高ではなく**当選額(gross)側に加算**する。

## 1. 仕様(ユーザー指示のUI)

分配設定(コイン・装備の売却価格入力の並び)に **「追加報酬」セクション**を設ける。

- **「+ 追加報酬」ボタン**で入力行を任意個数追加できる(初期状態は0行=何も表示しない)
- 各行: **メンバー選択(保存PTのメンバーから選ぶセレクト)** + **報酬NESO(数値入力)** + **削除ボタン**
- **5%販売手数料は引かない**(既に受け取り済みのNESOのため。コイン・装備・FT Itemとは異なる)
- 同一メンバーに複数行を追加できる(**合算**する)
- 金額の**空欄は 0**(LULU-126 準拠)。不正値(非数字・負値・桁あふれ)は従来どおりエラー
- ボスごとの設定(Lucid / Will で独立。既存の include / レート / 売却額と同じ扱い)
- **永続化しない**(既存の分配設定と同様に state のみ=LULU-099 の事実に合わせる)
- 行の説明文(新規i18nキー・6ロケール): 「ラッフル以外で受け取り、PT内で分配するNESO(キャリー報酬など)。手数料は引かれません。」

## 2. 計算(`domain/settlement.js`)

- 入力形式: `extraRewards: [{ rowId, memberId, amountNeso }]`(配列。順序は表示順)
- メンバーごとに合算し、**そのメンバーの gross に加算**(手数料なし)
- 合計は当然 `total` に含まれ、`baseShare` も増える
- `transferableNeso` にも**加算する**(受け取り済みの現物NESOであり送金原資になるため)
- カテゴリ別合計に `extraReward` を追加
- `memberId` が保存PTに存在しない行は `invalid_extra_reward_member` エラー

## 3. 表示

- **カテゴリ別合計**: 「追加報酬」行(合計が0または行が無ければ非表示)
- **メンバー別テーブル**: 「追加報酬」列(**合計が0なら非表示**=LULU-127 の自動非表示ルールに追加)
- **共有画像**: 同じく合計が0なら列を出さない(列が増えるのは実際に使った週だけ)
- **送金通知テキスト**: 変更不要(送金額のみのため)

## 4. 受け入れ基準(数値)

1. 6人・各当選60,000,000・m3に追加報酬60,000,000 → **m3が50,000,000支払い/他5人が各10,000,000受取**(送金5件・合計50,000,000)をテストで固定
2. 手数料が**引かれない**(60,000,000 を入れたら 60,000,000 が乗る。57,000,000 にならない)
3. 同一メンバー2行(30,000,000×2)が 60,000,000 として合算される
4. 空欄行は 0 として扱い計算が成立する。不正値はエラー
5. 追加報酬が0/未使用のとき、カテゴリ表・メンバー表・共有画像に**列が出ない**(既存の見た目が変わらない)
6. web テスト全緑・build 成功・6ロケールパリティ・**サーバー無変更**(`git diff` で server/ が空)

## 5. 変わってはいけない

- 5%手数料の適用範囲(コイン・装備・FT Item のみ)、PC除算、送金アルゴリズム、メンバー順正規化
- **持ち越しの ±0 チェックは維持**(本件の解決には不要であり、外すと誤結果を素通しするため)
- 新規npm依存 0
