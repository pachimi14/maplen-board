## 0. 目的と背景

- **要件を一文で**: **Lv225+ の全キャラを取り切れるようにし、上限に達した場合は必ず気づけるようにする。**
- **不具合(実測で確定)**:
  - 上限の正体 = **`RANKING_MAX_PAGES=800` × `API_MAX_PAGE_SIZE=10` = 8,000件**
  - **2026-07-29 に初到達**し、以降**7日連続で切り捨て**(07-29〜08-02・08-05 が 8,000ちょうど、08-03/08-04 が 7,999)
  - 公開中の v2 も `characterCount = 8000` で**切り捨て済みのまま配信**
  - **上限到達時に警告が一切出ない**(ループは「空ページ」「10件未満」では `logger.info` を出すが、**`max_pages` を使い切った場合は黙って抜ける**)→ **1週間気づけなかった原因**
- **復旧不可**: API は現在のランキングしか返さないため、**07-29〜08-05 の 8,000位以降は永久欠測**。今後分のみ是正できる。
- **推定影響**: 増加ペース約25件/日から、現在の実人口は **8,150〜8,200 前後**と推定 → **毎日150〜200人が欠落**。

## 2. 設計

### 2.1 上限の引き上げ(ユーザー承認済み)
- **`RANKING_MAX_PAGES`: 800 → 2000**(= **20,000件**)。`config.py` の既定値も揃える。
- **完全撤廃はしない**理由: ループの自然終了は「空ページ」「10件未満のページ」に依存しており、**API が異常に常時10件を返し続けると無限ループ**になる。2000ページは現在の増加ペース(約25件/日)で**十数年分の余裕**があり、実質無制限として機能しつつ暴走時の安全弁を残す。
- **実行時間への影響はほぼ無い**: `RANKING_REQUEST_DELAY_SEC=0.8` だが、**データが尽きた時点でループは止まる**ため、実人口 8,200 なら約 820 ページ ≒ 11分で従来と同等。

### 2.2 静かな切り捨ての可視化(**LULU-004 に触れない形**)
- **取得ループの中には手を入れない**。**取得完了後(呼び出し側)で判定**する。
- 判定: **取得件数が `max_pages × API_MAX_PAGE_SIZE` に達していたら、上限で打ち切られた可能性が高い**ため **`logger.warning`** を出す。
- 警告文に含める: **取得件数 / 上限値(`max_pages` と換算件数)/ 「上限に達したため取り切れていない可能性がある」旨 / 対処(`RANKING_MAX_PAGES` を上げる)**。
- **挙動は変えない**(警告を出すだけ。run を失敗させない)。理由: 取得自体は成功しており、部分データでも当日分として保存する方が欠測より良い。**気づける状態にすることが目的**。
